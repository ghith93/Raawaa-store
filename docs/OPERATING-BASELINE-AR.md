## 1. ترتيب مصادر الحقيقة

عند وجود تعارض، يُطبّق الترتيب التالي:

1. أحدث توجيه صريح من مالك المشروع.
2. الإعدادات المركزية الفعلية في `js/config.js` لسلوك الموقع المنشور، بعد التحقق من نسخة البناء.
3. اختبارات الكود ونتائج CI المطابقة لنفس SHA.
4. وثائق التشغيل الحديثة التي تحمل حالة وتاريخًا واضحين.
5. الخطط والمسودات والوثائق التاريخية؛ لا تُعامل كقرارات نافذة.

لا تُنسخ الأسعار أو الرسوم من خطة قديمة إلى الموقع أو المنشورات قبل مطابقتها مع المالك والإعداد المركزي.

## 4. حقيقة رحلة الطلب

الموقع الحالي يتيح للزائرة:

1. استعراض المنتج والأحجام.
2. اختيار الخيارات المتاحة.
3. مراجعة سلة وحساب مرجعي.
4. فتح واتساب برسالة مجهزة.

**فتح واتساب لا يثبت إرسال الرسالة أو استلامها.** والرسالة لا تصبح طلبًا مؤكدًا إلا بعد تأكيد التوفر والسعر والمنطقة والدفع وموعد التسليم. لا توجد بوابة دفع أو مخزون حي أو إثبات بأن كل فتح لواتساب يسجل طلبًا تلقائيًا.

يجب الفصل في التقارير بين:
- زيارة الصفحة.
- النقر على واتساب.
- رسالة واردة فعلًا.
- طلب مؤكد.
- طلب جرى تجهيزه.
- طلب تم تسليمه وتحصيل قيمته.
- إلغاء أو رفض أو استرجاع.

لا تُعلن مبيعات أو معدلات تحويل دون سجل قابل للتحقق، ولا تُعامل أهداف الخطط كتوقعات أو نتائج.

## 5. قواعد العلامة والمحتوى

- التموضع: عناية تجميلية راقية للشعر، برسالة واضحة وتجربة شراء موثوقة.
- تبقى الصيغة الكاملة ونسب التركيبة وتفاصيل التصنيع سرية، ولا تُنشر في الموقع أو المستودعات العامة أو مطالبات النماذج الخارجية.
- تُذكر فوائد تجميلية فقط عندما تكون صحيحة ومدعومة، مثل تحسين مظهر اللمعان والنعومة وتقليل مظهر الهيشان؛ لا وعود علاجية أو نتائج مضمونة.
- لا تقييمات أو شهادات أو صور قبل/بعد مختلقة. تستخدم تجارب حقيقية بموافقة أصحابها.
- لا ندرة مصطنعة ولا مخزون أو خصومات أو مواعيد غير مؤكدة.
- التصورات المولدة ليست دليلًا على شكل المخزون الفعلي. يجب ألا توحي الصور بأن لقطة التصميم صورة فوتوغرافية لعبوة مسلّمة.
- توحيد وعد الرد ومدة التجهيز والتوصيل وسياسة الإرجاع قبل عرضها على العميلة.

## 6. قياس المبيعات

لا توجد في هذا المرجع بيانات مبيعات حقيقية مثبتة. لذلك لا تُستخدم الأهداف الموجودة في خطط البيع بوصفها نتائج.

الحد الأدنى لسجل الأداء هو أعداد مجمعة لا تتضمن أسماء أو أرقام هواتف أو تفاصيل شخصية:
- الرسائل الواردة.
- الطلبات المؤكدة.
- الطلبات المسلّمة والمحصّلة.
- الإلغاءات والرفض والاسترجاع.
- متوسط قيمة الطلب.
- تكلفة التوصيل الفعلية حسب المنطقة.
- هامش المساهمة بعد التكاليف الفعلية.

لا تُرسل بيانات العميلات إلى أدوات أو مزودين خارجيين غير معتمدين.

## 7. حماية المعلومات

المستودع الحالي عام. لذلك يجب ألا يحتوي أي ملف عام أو سجل CI أو Issue أو PR على:
- أسرار أو مفاتيح أو رموز وصول.
- بيانات عميلات أو طلبات قابلة للتعرف.
- الصيغة الكاملة أو نسب المكونات أو أسرار التصنيع.
- تكاليف الموردين أو هوامش الربح أو شروط التفاوض أو تفاصيل العمولات وخطط التوزيع الخاصة.

إزالة ملف في commit جديد لا تمحو محتواه من تاريخ Git السابق. وأي معالجة للتاريخ أو تغيير لخصوصية المستودع قرار منفصل يحتاج تقييم أثره على Cloudflare Pages وGitHub Actions والتكاملات قبل التنفيذ. لا تدّعِ أن البيانات التاريخية أزيلت ما لم يُثبت ذلك.

## 8. بوابة اعتماد أي تغيير

قبل اعتبار أي تغيير جاهزًا:
- تحديد الفرع وSHA والملفات المملوكة للمهمة.
- فحص التعارض مع PRs والفروع المفتوحة.
- تشغيل الاختبارات ذات الصلة، ثم مجموعة الفحوص الكاملة المتاحة.
- التحقق من نسخة البناء، لا المصدر فقط.
- مراجعة نسخة الهاتف ومسار الشراء ورسالة واتساب.
- التحقق من الأسعار والرسوم بين الإعداد والواجهة والاختبارات والوثائق.
- ذكر ما لم يُختبر بوضوح.

الدمج أو النشر أو تعديل قاعدة بيانات حية أو أسرار أو صلاحيات لا يُستنتج من نجاح الاختبارات وحده؛ يلزم اتباع التفويض التشغيلي الحالي وحدوده.
