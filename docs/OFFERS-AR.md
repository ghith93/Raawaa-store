# خانات العروض والتخفيضات — دليل المالك

> هذا الملف يشرح كيف تفتح عرضًا وتوقفه، بلا لمس أي ملف تصميم.
> كل شيء يحدث في مكان واحد: `js/config.js` → مفتاح `offers.slots`.
> **لا يوجد عرض مفعّل الآن.** الأسعار المعتمدة 13 / 16 / 25 دولارًا هي المعلنة في الموقع،
> وأي تخفيض لا يُنشر إلا بكتابة `enabled: true` بيد المالك.

---

## ١. كيف تفتح عرضًا في دقيقة

افتحي `js/config.js` وابحثي عن `offers:`. ستجدين ثلاثة أسطر جاهزة معلّقة بـ`//`.
احذفي `//` من بداية السطر، وغيّري `enabled: false` إلى `enabled: true`، واحفظي.

```js
offers: {
  maxPercent: 30,
  slots: [
    { id: 'launch', label: 'عرض الإطلاق', type: 'percent', value: 15, sizeId: 'serum-50', enabled: true, endsAt: '2026-11-30', badge: 'إطلاق' }
  ],
  note: '…'
}
```

ما يحدث تلقائيًا بعد الحفظ والنشر:

| المكان | ما تراه الزبونة |
|---|---|
| بطاقة الحجم | السعر القديم مشطوب + السعر الجديد + شارة «−15% · عرض الإطلاق» |
| سعر العبوة المختارة | «$16 ~~$13.60~~ 50 مل» بنفس الشطب؛ الحساب الداخلي $13.60 |
| السلة | صف مستقل: «عرض: عرض الإطلاق → − $2.40»؛ الخصم الداخلي $2.40 |
| المجموع | يُحسب بدقة بعد العرض ثم يُطبَّق خصم شام كاش ثم التوصيل، وتُعرض القيمة الدقيقة بالسنتات |
| رسالة واتساب | «— $13.60 للواحدة = … (بدل $16 — عرض «عرض الإطلاق»)» وسطر خصم دقيق مستقل |
| التقدير والحاسبة | يعيدان الحساب نفسه، فلا يختلف رقمان |

> **مهم — الفرق بين عرض لحجم وعرض للطلب كله:** الشطب على بطاقة الحجم يظهر فقط حين
> تكتبين `sizeId`. بلا `sizeId` يُطبَّق الخصم على قيمة المنتجات كلها ويظهر كصف مستقل في
> السلة، **ولا** يُشطب سعر أي حجم. المثال أعلاه مقيَّد بـ`serum-50` لهذا السبب.

## ٢. الأنواع الأربعة

| النوع | المعنى | مثال | يسري على |
|---|---|---|---|
| `percent` | نسبة مئوية | `value: 15` = ‎−15% | حجم بعينه إن كُتب `sizeId`، وإلا على قيمة المنتجات كلها |
| `amount` | مبلغ ثابت بالدولار | `value: 5` = ‎−5$ | قيمة المنتجات كلها (لا على حجم واحد) |
| `sizePrice` | سعر جديد لحجم واحد | `sizeId: 'serum-100', value: 22` | الحجم المذكور فقط |
| `bundle` | **عرض عبوة أو عبوتين أو ثلاث** | `qty: 2, value: 28` = عبوتان بـ $28 | حجم بعينه إن كُتب `sizeId`، وإلا على كل حجم يكون فيه أرخص فعلًا |

`amount` لا يُخصم من التوصيل ولا من إضافة العطر، ولا ينزل بالطلب تحت الصفر.

وكذلك **خصم شام كاش (10%) يُحسب على قيمة المنتجات وحدها**: لا على إضافة العطر ($2 للعبوة)
ولا على التوصيل. مثال 50 مل + عطر: المنتجات $16 والعطر $2، فالخصم $1.60 والإجمالي $16.40
داخل حماة، و$18.40 خارجها.

### عرض العبوة (`bundle`) بالتفصيل

- `qty` عدد العبوات في العرض (١–١٠)، و`value` **سعرها كاملة** لا سعر الواحدة.
- يعمل على كمية الحجم الواحد: عبوتان من 50 مل تُقيَّمان بسعر 50 مل، والكوبون نفسه
  لا يخلط 30 مل مع 100 مل لأن سعريهما مختلفان.
- **أفضل تركيبة تُحسب تلقائيًا:** ثلاث عبوات من 50 مل مع «عبوتان بـ $28» = عبوتان + واحدة بسعرها ($44)،
  وأربع عبوات = $56. وثلاث من 100 مل مع «٣ بـ $66» = $66، وأربع = $91. لا خصم متكرر على العبوة نفسها.
- إذا وُجد عرضان للعبوات (واحد لحجم وواحد لكل الأحجام)، يُختار الأرخص للزبونة.
- عرض العبوة **لا يتضاعف** مع نسبة الحجم: للعبوة الواحدة يُطبَّق الأرخص فقط، ثم شام كاش على الناتج.
- عرض `qty: 1` هو «سعر عبوة واحدة» لكل حجم يقبله — ويُهمَل تلقائيًا على أي حجم سعره أقل من قيمة العرض.

أمثلة جاهزة (غير مفعّلة):

```js
{ id: 'two-50', label: 'عبوتان للاستعمال اليومي', type: 'bundle', qty: 2, sizeId: 'serum-50', value: 28, enabled: false },
{ id: 'three-100', label: 'ثلاث عبوات كبيرة', type: 'bundle', qty: 3, sizeId: 'serum-100', value: 66, enabled: false },
{ id: 'single-100', label: 'عبوة كبيرة بسعر خاص', type: 'bundle', qty: 1, sizeId: 'serum-100', value: 22, enabled: false }
```

## ٣. الحقول الاختيارية

| الحقل | الوظيفة |
|---|---|
| `startsAt` | «YYYY-MM-DD» — لا يبدأ العرض قبل هذا اليوم |
| `endsAt` | «YYYY-MM-DD» — يتوقف وحده بعد آخر يوم (يوم الانتهاء نفسه داخل العرض) |
| `badge` | الشارة القصيرة؛ إن تُركت تُحسب تلقائيًا: ‎−15% أو ‎−5$ أو «سعر خاص» |
| `label` | الاسم الذي تقرأه الزبونة في السلة والرسالة — إلزامي |

التاريخ يُقارن بتاريخ جهاز الزائرة. لا حاجة لأي تدخّل عند انتهاء العرض.

## ٤. قواعد الحماية (مقصودة، لا تُغيَّر بلا قرار)

1. **الفشل المغلق:** خانة بلا `enabled: true` لا تعمل. نسيان التفعيل = لا خصم، لا العكس.
2. **سقف النسبة** `maxPercent: 30`. أي نسبة أعلى تُهمَل كاملة — حماية من صفر زائد أو فاصلة في غير مكانها.
   والسقف نفسه يحكم عروض العبوات: عرض يخفض سعر العبوة أكثر من 30% لا يعمل (يُهمَل لكامل العرض، لا يُقصّ).
3. **سعر أعلى من الأصلي مرفوض:** `sizePrice` لا يعمل إلا إذا كان أقل من سعر الحجم المعلن.
4. **حجم غير موجود مرفوض:** `sizeId` يجب أن يطابق `serum-30` أو `serum-50` أو `serum-100`.
5. **عرض واحد لكل نطاق:** الأول في المصفوفة هو الذي يعمل. الترتيب = الأولوية.
6. **التراكم مع شام كاش مقصود ومعلَن:** العرض أولًا، ثم ‎−10% شام كاش على ناتج **المنتجات**، ثم التوصيل.
   مثال 50 مل مع عرض ‎−10%: الحساب الدقيق 16 ← 14.40 ← 12.96 (شام كاش داخل حماة، توصيل مجاني)؛ تُعرض القيم الدقيقة $14.40 ثم $12.96.
   إضافة العطر والتوصيل خارج وعاء الخصم دائمًا.
7. **بعد الإيقاف:** احذف السطر أو اجعله `enabled: false` — الأسعار تعود فورًا إلى 13/16/25.

## ٥. أفكار عروض جاهزة (مقترحة، غير مفعّلة)

هذه اقتراحات صياغة فقط. القيم والتواريخ قرار المالك، ولا تُنشر حتى يكتبها بنفسه:

| الفكرة | الخانة |
|---|---|
| عرض إطلاق محدد المدة | `type: 'percent', value: 10, endsAt: '2026-11-15'` |
| سعر خاص للعبوة الكبيرة | `type: 'sizePrice', sizeId: 'serum-100', value: 22` |
| خصم على الطلب كله | `type: 'amount', value: 3` |
| سعر الحجم الصغير للتجربة | `type: 'sizePrice', sizeId: 'serum-30', value: 11` |
| عبوتان من 50 مل | `type: 'bundle', qty: 2, sizeId: 'serum-50', value: 28` |
| ثلاث عبوات كبيرة | `type: 'bundle', qty: 3, sizeId: 'serum-100', value: 66` |
| عبوة واحدة بسعر خاص | `type: 'bundle', qty: 1, value: 22` (تعمل على 100 مل فقط؛ 30 مل و50 مل أرخص منها أصلًا) |

قبل تفعيل أي عرض: تأكدي أن السعر بعد العرض يبقى فوق التكلفة (3–4$ للعبوة) + التوصيل.
مثال: 30 مل بسعر 11$ مع شام كاش داخل حماة = 9.90$ صافيًا ← 5.90$ فوق أعلى تكلفة مقدرة.

## ٦. نفس الرقم في الخادم والواجهة

**طريقة العرض:** الواجهة الحالية تعرض المبالغ الدقيقة، مع الأجزاء العشرية عند وجودها (مثلًا $14.40)، ولا تغيّر السعر أو التقدير إلى أقرب دولار. الحساب الداخلي والاختبارات والخادم تستخدم السنتات الدقيقة. لا يُعامل التقدير على أنه مبلغ تحصيل نهائي؛ السعر النهائي والتوفر يؤكدهما المالك عبر واتساب.

`order-system/order-core.mjs` يستورد محرّك العروض نفسه (`js/offers.js`) ويحسب الرقم من الإعدادات
المُوقَّعة، لا من رقم ترسله الزبونة. وتظل القيمة الدقيقة موحدة بالسنتات بين الواجهة والحساب الخلفي.
مطلوب بعد أي تعديل في الأسعار أو العروض: `npm run build:order` (يعيد بناء حزمة الـedge وبصمة الإعدادات).
اختبار التطابق: `node --test order-system/order-core.test.mjs` — ومنه حالة عرض 10% على 50 مل:
الواجهة 12.96 والخادم 12.96.

## ٧. ما يجب فعله بعد أي عرض

- ارفع `CACHE_VERSION` في `sw.js` — يفعله سكربت البناء تلقائيًا عند النشر، وأيضًا في `npm run build`.
- شغّل `npm run test:offers` (23 فحصًا بلا شبكة) و`npm run build:order` إن تغيّرت الأسعار أو العروض.
- بعد النشر: افتح الصفحة على الآيفون وتحقق أن السعر المشطوب يطابق السعر الجديد، وأن رسالة واتساب تحمل سطر العرض.
- **JSON-LD:** يظل على السعر المعلن (13/16/25) لأن العرض مؤقت. إن صار العرض دائمًا، حدِّث `lowPrice`/`highPrice` في `index.html` و`serum.html` معًا.
