# خانات العروض والتخفيضات — دليل المالك

> هذا الملف يشرح كيف تفتح عرضًا وتوقفه، بلا لمس أي ملف تصميم.
> كل شيء يحدث في مكان واحد: `js/config.js` → مفتاح `offers.slots`.
> **لا يوجد عرض مفعّل الآن.** الأسعار المعتمدة 19 / 26 / 29 دولارًا هي المعلنة في الموقع،
> وأي تخفيض لا يُنشر إلا بكتابة `enabled: true` بيد المالك.

---

## ١. كيف تفتح عرضًا في دقيقة

افتحي `js/config.js` وابحثي عن `offers:`. ستجدين ثلاثة أسطر جاهزة معلّقة بـ`//`.
احذفي `//` من بداية السطر، وغيّري `enabled: false` إلى `enabled: true`، واحفظي.

```js
offers: {
  maxPercent: 30,
  slots: [
    { id: 'launch', label: 'عرض الإطلاق', type: 'percent', value: 15, enabled: true, endsAt: '2026-11-30', badge: 'إطلاق' }
  ],
  note: '…'
}
```

ما يحدث تلقائيًا بعد الحفظ والنشر:

| المكان | ما تراه الزبونة |
|---|---|
| بطاقة الحجم | السعر القديم مشطوب + السعر الجديد + شارة «−15% · عرض الإطلاق» |
| سعر العبوة المختارة | «$26 ~~≈ $22~~ 50 مل» بنفس الشطب؛ الحساب الداخلي $22.10 |
| السلة | صف مستقل: «عرض: عرض الإطلاق → − ≈ $4»؛ الخصم الداخلي $3.90 |
| المجموع | يُحسب بدقة بعد العرض ثم يُطبَّق خصم شام كاش ثم التوصيل، ويُعرض الكسر مقربًا مع `≈` |
| رسالة واتساب | «— ≈ $22 للواحدة = … (بدل $26 — عرض «عرض الإطلاق»)» وسطر خصم تقريبي مستقل |
| التقدير والحاسبة | يعيدان الحساب نفسه، فلا يختلف رقمان |

## ٢. الأنواع الأربعة

| النوع | المعنى | مثال | يسري على |
|---|---|---|---|
| `percent` | نسبة مئوية | `value: 15` = ‎−15% | حجم بعينه إن كُتب `sizeId`، وإلا على قيمة المنتجات كلها |
| `amount` | مبلغ ثابت بالدولار | `value: 5` = ‎−5$ | قيمة المنتجات كلها (لا على حجم واحد) |
| `sizePrice` | سعر جديد لحجم واحد | `sizeId: 'serum-100', value: 26` | الحجم المذكور فقط |
| `bundle` | **عرض عبوة أو عبوتين أو ثلاث** | `qty: 2, value: 46` = عبوتان بـ $46 | حجم بعينه إن كُتب `sizeId`، وإلا على كل حجم يكون فيه أرخص فعلًا |

`amount` لا يُخصم من التوصيل ولا من إضافة العطر، ولا ينزل بالطلب تحت الصفر.

### عرض العبوة (`bundle`) بالتفصيل

- `qty` عدد العبوات في العرض (١–١٠)، و`value` **سعرها كاملة** لا سعر الواحدة.
- يعمل على كمية الحجم الواحد: عبوتان من 50 مل تُقيَّمان بسعر 50 مل، والكوبون نفسه
  لا يخلط 30 مل مع 100 مل لأن سعريهما مختلفان.
- **أفضل تركيبة تُحسب تلقائيًا:** ثلاث عبوات مع «عبوتان بـ $46» = عبوتان + واحدة بسعرها (72$)،
  وأربع عبوات مع «٣ بـ 66$» = 3 + واحدة. لا خصم متكرر على العبوة نفسها.
- إذا وُجد عرضان للعبوات (واحد لحجم وواحد لكل الأحجام)، يُختار الأرخص للزبونة.
- عرض العبوة **لا يتضاعف** مع نسبة الحجم: للعبوة الواحدة يُطبَّق الأرخص فقط، ثم شام كاش على الناتج.
- عرض `qty: 1` هو «سعر عبوة واحدة» لكل حجم يقبله — ويُهمَل تلقائيًا على أي حجم سعره أقل من قيمة العرض.

أمثلة جاهزة (غير مفعّلة):

```js
{ id: 'two-50', label: 'عبوتان للاستعمال اليومي', type: 'bundle', qty: 2, sizeId: 'serum-50', value: 46, enabled: false },
{ id: 'three-any', label: 'ثلاث عبوات', type: 'bundle', qty: 3, value: 75, enabled: false },
{ id: 'single-100', label: 'عبوة كبيرة بسعر خاص', type: 'bundle', qty: 1, sizeId: 'serum-100', value: 26, enabled: false }
```

## ٣. الحقول الاختيارية

| الحقل | الوظيفة |
|---|---|
| `startsAt` | «YYYY-MM-DD» — لا يبدأ العرض قبل هذا اليوم |
| `endsAt` | «YYYY-MM-DD» — يتوقف وحده بعد آخر يوم (يوم الانتهاء نفسه داخل العرض) |
| `badge` | الشارة القصيرة؛ إن تُركت تُحسب تلقائيًا: ‎−15% أو ‎−5$ أو «سعر خاص» |
| `label` | الاسم الذي تقرأه الزبونة في السلة والرسالة — إلزامي |

التاريخ يُقارن بتاريخ جهاز الزائرة. لا حاجة لأي تدخّل عند انتهاء العرض.

## ٤. قواعد الحماية (مقصودة، لا تُغيَّر بلا قرار)

1. **الفشل المغلق:** خانة بلا `enabled: true` لا تعمل. نسيان التفعيل = لا خصم، لا العكس.
2. **سقف النسبة** `maxPercent: 30`. أي نسبة أعلى تُهمَل كاملة — حماية من صفر زائد أو فاصلة في غير مكانها.
   والسقف نفسه يحكم عروض العبوات: عرض يخفض سعر العبوة أكثر من 30% لا يعمل (يُهمَل لكامل العرض، لا يُقصّ).
3. **سعر أعلى من الأصلي مرفوض:** `sizePrice` لا يعمل إلا إذا كان أقل من سعر الحجم المعلن.
4. **حجم غير موجود مرفوض:** `sizeId` يجب أن يطابق `serum-30` أو `serum-50` أو `serum-100`.
5. **عرض واحد لكل نطاق:** الأول في المصفوفة هو الذي يعمل. الترتيب = الأولوية.
6. **التراكم مع شام كاش مقصود ومعلَن:** العرض أولًا، ثم ‎−10% شام كاش على الناتج، ثم التوصيل.
   مثال 50 مل مع عرض ‎−10%: الحساب الدقيق 26 ← 23.40 ← 21.06 (شام كاش داخل حماة، توصيل مجاني)؛ العرض للعميلة يكون `≈ $23` ثم `≈ $21`.
7. **بعد الإيقاف:** احذف السطر أو اجعله `enabled: false` — الأسعار تعود فورًا إلى 19/26/29.

## ٥. أفكار عروض جاهزة (مقترحة، غير مفعّلة)

هذه اقتراحات صياغة فقط. القيم والتواريخ قرار المالك، ولا تُنشر حتى يكتبها بنفسه:

| الفكرة | الخانة |
|---|---|
| عرض إطلاق محدد المدة | `type: 'percent', value: 10, endsAt: '2026-11-15'` |
| سعر خاص للعبوة الكبيرة | `type: 'sizePrice', sizeId: 'serum-100', value: 26` |
| خصم على الطلب كله | `type: 'amount', value: 3` |
| سعر الحجم الصغير للتجربة | `type: 'sizePrice', sizeId: 'serum-30', value: 16` |
| عبوتان من 50 مل | `type: 'bundle', qty: 2, sizeId: 'serum-50', value: 46` |
| ثلاث عبوات بأي حجم | `type: 'bundle', qty: 3, value: 75` |
| عبوة واحدة لجميع الأحجام | `type: 'bundle', qty: 1, value: 26` (لا تعمل على 30 مل لأن سعرها 19$) |

قبل تفعيل أي عرض: تأكدي أن السعر بعد العرض يبقى فوق التكلفة (3–4$ للعبوة) + التوصيل.
مثال: 30 مل بسعر 16$ مع شام كاش داخل حماة = 14.40$ صافيًا ← 10.40$ فوق أعلى تكلفة مقدرة.

## ٦. نفس الرقم في الخادم والواجهة

**طريقة العرض:** أسعار المنتج المرجعية تظهر أعدادًا صحيحة بلا فواصل آلاف. أي خصم أو إجمالي محسوب يحوي كسور دولار يظهر مقربًا لأقرب دولار ومسبوقًا بـ `≈` (مثلًا `≈ $23`)؛ الحساب الداخلي والاختبارات والخادم يبقون بالسنتات الدقيقة (مثلًا 2340 سنتًا). لا تُحذف علامة التقريب ولا يُعامل التقدير المقرب كمبلغ تحصيل نهائي. سعر الملليلتر مقياس مقارنة ويحتفظ بدقته العشرية.

`order-system/order-core.mjs` يستورد محرّك العروض نفسه (`js/offers.js`) ويحسب الرقم من الإعدادات
المُوقَّعة، لا من رقم ترسله الزبونة. يبقى الرقم الدقيق موحدًا بالسنتات بين الواجهة والحساب الخلفي، حتى لو عُرض للزبونة مقربًا مع `≈`.
مطلوب بعد أي تعديل في الأسعار أو العروض: `npm run build:order` (يعيد بناء حزمة الـedge وبصمة الإعدادات).
اختبار التطابق: `node --test order-system/order-core.test.mjs` — ومنه حالة عرض 10% على 50 مل:
الواجهة 21.06 والخادم 21.06.

## ٧. ما يجب فعله بعد أي عرض

- ارفع `CACHE_VERSION` في `sw.js` — يفعله سكربت البناء تلقائيًا عند النشر، وأيضًا في `npm run build`.
- شغّل `npm run test:offers` (37 فحصًا بلا شبكة) و`npm run build:order` إن تغيّرت الأسعار أو العروض.
- بعد النشر: افتح الصفحة على الآيفون وتحقق أن السعر المشطوب يطابق السعر الجديد، وأن رسالة واتساب تحمل سطر العرض.
- **JSON-LD:** يظل على السعر المعلن (19/26/29) لأن العرض مؤقت. إن صار العرض دائمًا، حدِّث `lowPrice`/`highPrice` في `index.html` و`serum.html` معًا.
