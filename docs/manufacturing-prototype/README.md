# نموذج محلي لمسار التصنيع حسب الطلب

هذا مجلد تجريبي مستقل داخل التوثيق، ولا يستبدل المتجر العام أو يغير صفحات البيع والأسعار والسياسات. لا تشغّل هذا النموذج على استضافة عامة ولا تنشره كمسار إنتاج.

## التشغيل والاختبار

يتطلب Node.js 22.22 أو أحدث، بلا حزم إضافية:

```sh
node --test docs/manufacturing-prototype/*.test.mjs
node docs/manufacturing-prototype/server.mjs
```

ثم افتح `http://localhost:4174`. يمكن تغيير المنفذ باستخدام `PORT=...`، والاستماع الافتراضي `0.0.0.0` مخصص للمعاينة المحلية في بيئة التطوير؛ لا يعني أن التطبيق مهيأ للنشر.

الحالة مخزنة في الذاكرة وتُمحى عند إيقاف الخادم. جميع الجلسات على الخادم نفسه تشترك في بيانات التجربة، بينما اختيار شخصية العرض محفوظ في cookie محلي. مبدّل الشخصيات **ليس** تسجيل دخول ولا مصادقة أو إثبات هوية إنتاجيًا. توجد فحوص صلاحيات وعزل مصانع على الخادم لتجربة حدود النطاق فقط.

## خطوات التجربة المقترحة

1. **مصممة المنتجات:** إنشاء الاقتراح المحلي ثم إنشاء المواصفة v1. الاقتراح ثابت نصيًا، والحقول المعروضة اعتُمِدت بشريًا لأغراض المثال فقط.
2. **العمليات:** طلب مراجعة مصنع.
3. **المصنع التجريبي A:** إرسال عرض سعر اصطناعي. جرّب اختيار المصنع التجريبي B قبل ذلك لمشاهدة عزل البيانات والأوامر.
4. **مسؤول المتجر:** اعتماد المنتج ثم نشره في متجر العرض فقط.
5. **العميل التجريبي:** إنشاء طلب واحد (دون دفع).
6. **العمليات:** إنشاء أمر تصنيع واحد يثبت نسخة المواصفة الواردة في الطلب.
7. **المصنع A:** قبول الأمر، بدء الإنتاج، ثم إرساله إلى فحص الجودة.
8. **الجودة:** جرّب «محاكاة فشل بند». ستظهر إعادة العمل ويجب أن يُرفض تسجيل الشحنة. بعد ذلك بدّل إلى المصنع A وسجّل إعادة العمل، ثم عُد إلى الجودة وسجل اجتيازًا اصطناعيًا.
9. **العمليات:** سجل شحنة يدوية، وإقرار تسليم يدوي، ثم حدّث التتبع إلى «قيد النقل». يمكن تجربة «استثناء في التتبع» ثم إعادته إلى قيد النقل، قبل تسجيل «تسليم مدخل يدويًا».
10. **العميل التجريبي:** افتح مطالبة تأخير؛ ثم **الدعم:** أغلقها بملاحظة تدريبية.

كل إجراء يُتحقق منه على الخادم من حيث الدور والحالة. أزرار الواجهة ليست مصدر التفويض. مفتاح idempotency يمنع تكرار الطلب التجريبي وأمر التصنيع عند تكرار نفس الطلب.

## نطاق المحاكاة والحدود

- المنتج: دفتر A5 خيالي ضمن قرطاسية غير منظمة. لا يتعلق بمستحضر رواء ولا يصفه بأنه منخفض الحساسية.
- بيانات المواصفة، التكلفة والسعر والمهلة والقدرة والفحوص والطلب والشحنة والمطالبة كلها صناعية. المواصفة نص توضيحي وليست CAD أو رسمًا تنفيذيًا أو شهادة مطابقة.
- «AI» اقتراح ثابت في الكود؛ لا اتصال بمزود AI، ولا صور مولّدة، ولا أسرار أو مفاتيح.
- لا قاعدة بيانات أو migrations أو Supabase، ولا دفع أو شحن أو مراسلات أو مصنع حقيقي. الدفع لا يخصم أموالًا، والتتبع إقرار يدوي اصطناعي لا يثبت واقعة خارجية.
- حالة فشل الجودة تمنع إنشاء الشحنة داخل النموذج. تُحفظ نتيجة الفشل وإعادة العمل وإعادة الفحص ضمن دورة الذاكرة الحالية.
- أُدرجت حالات شحنة استثناء، ومطالبة بسبب تأخير/ضرر/اختلاف مواصفة/أخرى، ومسار حل الدعم. لكن لا توجد أدلة ضرر فعلية أو سياسة تعويض أو رد أموال أو إرجاع أو ربط مع شركة شحن.

## ما يؤجل قبل تصميم منتج حقيقي

اعتماد هوية وتفويض حقيقيين، نموذج تهديد ومراجعة أمنية، تصميم بيانات وعزل مستأجرين دائم، إدارة أسرار، تدقيق قانوني ومالي وخصوصية، مراجعة سلامة ومطابقة حسب كل فئة، مواصفات هندسية قابلة للتصنيع واعتماد عينات فعلية، عروض وعقود موردين حقيقية، إدارة مشتريات ومخزون، قواعد الدفع والاسترجاع والنزاعات، شراكات شحن وتتبع موثقة، وإجراءات حوادث/مرتجعات/تعويضات مع مراجعة بشرية. لا يعتبر هذا النموذج دليلًا على جاهزية أي منها.
