# تقييم LiteLLM لمشروع رواء — 30 أكتوبر 2026

## الخلاصة

[LiteLLM](https://github.com/BerriAI/litellm) مناسب **نظريًا** لتوحيد استدعاءات عدة مزودين وإدارة بوابة نماذج عند توسّع المشروع؛ ليس محرك طلبات أو وكيلًا دائمًا أو نموذجًا مجانيًا بحد ذاته. لا نحتاجه لتشغيل المستشارين الحاليين: كلاهما يتصلان مباشرة بـCloudflare Workers AI عبر JavaScript، بنموذجين محددين وصلاحيات وحدود ضيقة. إضافة خدمة Python أو خادم Proxy الآن تزيد الصيانة والهجوم والتكلفة المحتملة قبل وجود حاجة مثبتة. **القرار: مرشح لاحق، لم يُثبّت ولم يُربط ولم يُجرَ اتصال حقيقي من خلاله.**

## ما فُحص

- عند قراءة GitHub API: 62,329 نجمة، المستودع غير مؤرشف، أحدث إصدار `v1.106.6` بتاريخ 28 أكتوبر 2026. هذه أرقام متغيرة وليست ضمانًا للأمان.
- يقدّم [SDK Python وخادم Proxy بواجهة موحدة](https://github.com/BerriAI/litellm)، ويعرض خصائص مفيدة مثل توجيه النماذج وتتبع الاستهلاك. [قائمة المزودين](https://berriai.github.io/litellm/) تذكر Cloudflare Workers AI، كما توضح [ملاحظات إصدار v1.91.0](https://docs.litellm.ai/release_notes/v1.91.0/v1-91-0) دعم مجموعة من نماذج Cloudflare وواجهة متوافقة مع OpenAI. **لم نختبر نموذجي Qwen وGPT-OSS الموجودين في حساب رواء عبر LiteLLM**؛ اختلاف إصدارات وواجهات الطلبات أو الميزات وارد.
- GitHub يصنف الرخصة `NOASSERTION`؛ [ملف LICENSE](https://github.com/BerriAI/litellm/blob/main/LICENSE) يحدد MIT خارج `enterprise/`، فيما يخضع `enterprise/` لرخصته الخاصة. لا يُفترض أن كل الميزات أو الخدمة المستضافة مجانية أو MIT؛ راجع الرخصة المحددة والميزات عند اعتماد نسخة معينة.
- [تسعير Cloudflare Workers AI](https://developers.cloudflare.com/workers-ai/platform/pricing/) وحدود الحساب تظل سارية؛ LiteLLM لا يوفر الاستدلال مجانًا ولا يضمن سقف تكلفة الحساب. استضافة Proxy وقاعدة بياناته المحتملة والمراقبة تتطلب موارد وتكلفة تشغيل إضافية. لا fallback إلى مزود مدفوع أو ترقية دون موافقة.
- خصوصية: Proxy وسيط يرى الطلبات والمفاتيح، وقد تسجّل مكوناته بيانات حسب التهيئة. يجب تقليل البيانات ومنع بيانات العملاء والأسرار في prompts والسجلات، وعزل مفاتيح الاستدلال عن DB وTelegram؛ تراجع إعدادات التتبع والتخزين والتشفير والصلاحيات قبل أي نشر.

## الأمن والاختبار

أبلغ المشروع رسميًا عن [حادثة سلسلة توريد في مارس 2026](https://docs.litellm.ai/blog/security-update-march-2026): حزمتا PyPI `1.82.7` و`1.82.8` احتوتا كودًا خبيثًا لسرقة بيانات اعتماد وأزيلتا؛ المشروع أعلن لاحقًا تدقيقًا وتحصينًا لمسار النشر. هذا لا يثبت أن الإصدار الحالي مخترق أو آمن تلقائيًا. لا يوجد في ملفات المستودع الحالية اعتماد مباشر على LiteLLM؛ لم يُجرَ تدقيق شامل لكل بيئة أو تبعية غير مباشرة تاريخية.

إذا أثبتت الحاجة المستقبلية تعدد المزودين: مراجعة النسخة وتبعياتها ورخصها ونشرات الأمان وتثبيت إصدارات وبصمات موثوقة، ثم تجربة داخل بيئة معزولة بلا أسرار أو بيانات عملاء واتصالات محدودة، وفحص أثر التتبع والأخطاء، والتكلفة والأهلية، ثم تجربة محدودة للحساب فقط بعد التأكد من المجاني. التثبيت الثابت أو التجربة لا يضمنان السلامة؛ لا يُرسل مفتاح إنتاج إلى بيئة غير موثوقة. لا تستعمل الإصدارين المصابين.

## التنفيذ الحالي: أساس مقارنة محلي

أُضيف `manager/model-evaluation.mjs` بخمس حالات عربية اصطناعية مغلقة: سعر وتوصيل من `js/config.js` الموثوق، سعر زيت غير معروف، ادعاء علاجي بلا دليل، ومحاولة حقن تعليمات بشأن المبيعات. المقيّم يتحقق من JSON والإجابة فقط ولا ينفذ أو يرسل أي طلب أو بيانات عميل. اختبارات الوحدة تحاكي النتائج الصحيحة والخاطئة وتثبت تغير القيم المتوقعة عند تغيير الإعدادات. هذه **ليست نتائج تقييم نموذج**، ولا تثبت جودة العربية أو مقاومة الحقن عمومًا. قبل أي مقارنة حية يلزم بناء مشغل محدود، اختبار عدم تجاوز 5 استدعاءات لكل نموذج والتوقف عند 429/403 والتحقق من الحصة، وعدم إرسال الإجابات المتوقعة ضمن prompt، ومراجعة النتائج؛ لم تُنفّذ استدعاءات جديدة لهذا التقييم.
