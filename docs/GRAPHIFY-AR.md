# Graphify في رواء

استُخدم مشروع [Graphify-Labs/graphify](https://github.com/Graphify-Labs/graphify) المفتوح بترخيص Apache-2.0 لتحليل اعتماديات الكود محليًا. استُخدم إصدار `graphifyy==0.9.97` في بيئة Python معزولة دون Cloud أو مفاتيح LLM. تحليل AST ليس دليلًا على سلوك التشغيل؛ قد يمر أقصر مسار عبر ملف اختبار بدل مسار تنفيذ حقيقي، لذا يجب مراجعة المصدر واختبار النتيجة.

لإعادة التحليل على جهاز تطوير (يلزم Python 3.10+ والإنترنت للتثبيت الأول فقط):

```sh
python3 -m venv .cache/graphify-venv
.cache/graphify-venv/bin/pip install 'graphifyy[sql]==0.9.97'
bash scripts/graphify-local.sh
```

ينسخ السكربت ملفات الكود المتتبعة المحددة فقط إلى مجلد مؤقت تحت `.cache`، ويشغل `graphify update --no-cluster` بلا مزود لغوي أو بيانات البيئة. لا يقرأ بيانات قاعدة البيانات أو صورًا أو ملفات أسرار أو ملفات غير متتبعة. النواتج المحلية متجاهلة في Git ولا تُنشر ضمن الموقع. يعتمد تثبيت PyPI على حزم طرف ثالث؛ لم تُثبَّت إضافات الاتصال الخارجي أو المراقبة أو الـhooks. يمكن استخدام `GRAPHIFY_BIN` لتحديد موقع تثبيت موثوق بديل.

أظهر المسح الأول 371 عقدة و851 رابطًا، ثم أظهر السكربت القابل للإعادة 430 عقدة و952 رابطًا ضمن الملفات المتتبعة وقت الفحص، وكان عميل الطلبات من العقد الأعلى اتصالًا. أثناء مراجعة مسار إعادة المحاولة كُشف أن رفض إعادة المحاولة قد يُعرض كرفض نهائي رغم عدم حسم محاولة سابقة؛ أصلحنا الحالة واختبرناها محليًا. استقبال الطلبات الحقيقي غير مفعّل.
