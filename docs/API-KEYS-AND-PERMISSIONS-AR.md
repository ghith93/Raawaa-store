# مفاتيح API والصلاحيات — الجواب الصادق

> طلبتَ: «ابحث في GitHub عن مشاريع تعطي API key ووظّفها لخدمتنا، أو أعطِ صلاحية إنشاء توكن
> في المستقبل عند الحاجة».
>
> **الجواب الصادق: ما طلبته غير ممكن تقنيًا، وأحدهما خطر لو نُفِّذ.**
> هذا الملف يشرح السبب ثم يعطي البديل الذي يعمل فعلًا.

---

## 1) «مشاريع تعطي API key» — ما وجدته فعليًا

بحثت في GitHub API بأكثر من استعلام. النتيجة ثلاث فئات، كلها غير صالحة لنا:

| # | الفئة | مثال حقيقي | الحكم | السبب |
|---|-------|-----------|-------|-------|
| 1 | **حمّامات مفاتيح** (key pools) تشارك مفاتيح أشخاص آخرين | `piyush-tyagi-13/llm-keypool` (⭐67) | ❌ **رفض قاطع** | المفاتيح مسروقة أو مُشاركة خلافًا لشروط الخدمة. استخدامها = انتهاك ToS + تعريض حسابك للحظر. وهي مفتاح **شخص آخر** يمكنه قراءة كل طلباتك |
| 2 | **وكلاء عكسيون** (reverse proxies) يلتفّون على الحصة المجانية | `opencode-unlimited-proxy`, `gemini-free-api` | ❌ **رفض قاطع** | التفاف صريح على حدود الخدمة = مخالفة ToS وتجميد الحساب. المستودعات نفسها بلا صيانة ولا ضمان، وبعضها يمرّر بياناتك لطرف ثالث |
| 3 | **قوائم خدمات مجانية** (curated lists) | `public-apis` (⭐492k), `free-for-dev` (⭐140k) | 🟡 **مقبول كمرجع فقط** | ليست مفاتيح جاهزة — هي فهارس خدمات لها حصص مجانية رسمية. مفيدة للدورة البحثية، لا للربط المباشر |

### القاعدة الحاكمة من توجيهك نفسه
أنت كتبتها: **«لا التفاف على شروط الخدمة، ولا استغلال حسابات متعددة».**
الفئتان 1 و2 تفعلان ذلك بالضبط. **لن أستخدمهما حتى لو طلبتَ صراحةً**، لأن الثمن
حسابك وحسابك هو القناة الوحيدة للإيراد. خدمة واحدة محظورة تعني صفر طلبات.

## 2) «صلاحية إنشاء توكن في المستقبل» — غير ممكن

**GitHub لا يسمح لأي توكن بإصدار توكن آخر.** لا توجد واجهة برمجية كهذه، بقرار أمني
مقصود: لو أمكن، لأمكن لأي توكن مسروق أن يولّد توكنات دائمة تنجو من الإلغاء.

فما يُفعل بدلًا من ذلك:

| البديل | كيف يعمل | الحكم |
|--------|----------|-------|
| **توكن طويل الأمد، محدود الصلاحية** | ما فعلتَه الآن: `Contents: Read and write` على مستودع واحد، 30 يومًا | ✅ **الأفضل — وهو ما نستخدمه** |
| **Cloudflare API Token** بدل GitHub | نشر الموقع (وهو ما يهم فعلًا) لا يحتاج GitHub إطلاقًا | ✅ مستخدم بالفعل |
| **GitHub App** | يستطيع تجديد توكناته بنفسه | ❌ مبالغة: يحتاج استضافة سيرفر + شهادة + صيانة — تعقيد بلا مقابل |
| **إعادة إصدار يدوية كل 30 يومًا** | خطوتان من الآيفون | ✅ مقبول — هذا ثمن الأمان الطبيعي |

**التوصية:** لا تمنح أي توكن صلاحية تتجاوز ما يحتاجه. عندما ينتهي `rawaa-deploy.1`
أعطني إشعارًا بسيطًا وأطلب منك توكنًا جديدًا — أو أعمل بدونه، فـ **الرفع على GitHub
ليس مسارًا حرجًا**: الموقع الحيّ يُنشر عبر Cloudflare مباشرة.

## 3) «ماذا أضع في خانة؟» — إجابة مباشرة

خانة **Token name** هي مجرد اسم تختاره أنت لتتعرّف على التوكن في القائمة؛ لا تؤثر على
أي شيء تقني. **ضع:**

```
rawaa-deploy
```

وإن أردت تمييزًا للمرحلة القادمة: `rawaa-deploy-2`.

أما الخانات التي **تؤثر** فعلًا فهذه، وهي المضبوطة في توكنك الحالي:

| الخانة | القيمة الصحيحة | لماذا |
|--------|----------------|-------|
| Repository access | `Only select repositories` → `Raawaa-store` | لا يصل لأي مستودع آخر |
| Permissions → Contents | `Read and write` | هذا وحده يكفي للرفع |
| Permissions → Metadata | `Read` (إجباري، تلقائي) | يضعه GitHub وحده |
| Permissions → Actions | `Read` ✅ مُتحقَّق أنه مفعّل | يسمح بقراءة نتائج CI — مفيد |
| Permissions → Secrets | — | **لا تضعه** إن لم تحتجه |
| Expiration | 30 يومًا | أقصر مدة مريحة |

**ما تحقّقتُ منه فعليًا على توكنك الحالي:**

| العملية | النتيجة |
|---------|---------|
| قراءة المستودع | ✅ 200 |
| قراءة نتائج CI | ✅ 200 — **74 تشغيلًا**، آخرها «Site checks: success» |
| قراءة تنبيهات الثغرات (Dependabot) | ✅ 204 |
| قراءة قائمة الأسرار | ✅ 200 — **0 سرّ** حاليًا |
| الدفع (push) | ✅ تمّ: `587e8d68` |
| حماية الفرع `main` | ❌ غير مفعّلة (404) |
| صلاحية Actions write | ❌ غير مفعّلة |
